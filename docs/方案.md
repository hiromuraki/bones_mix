# 方案

## 1. 可选方案

### 1.1. 方案 1：MediaPipe Pose（“缓兵之计”方案）

对甲方的可行性：极高。 就像我们之前聊的，不用配环境，不吃显卡，自带防抖，实时丝滑。如果你需要明早给甲方看个 Demo 稳住他们，立刻选这个。

对发论文的可行性：零。 这是一个 Google 封装好的成熟商业库，底层是 BlazePose。你把它拿来用，在学术上叫“调包”，没有任何算法创新（Novelty）。除非你的论文是写《基于 MediaPipe 的某某系统设计与实现》（典型的专硕/本科学位论文套路，学硕发小论文或者盲审大概率被毙）。

综合建议： 纯工程项目可以用，但绝对不能作为你毕业和发小论文的核心支柱。

> 评价：2D 效果还好，3D 效果非常糟糕，PASS

### 1.2. 方案 2：RTMPose + MotionAGFormer/MMCPose + 物理约束（“黄金破局”方案 🌟 强烈推荐）

这个方案简直是为你这个“软工学硕”量身定制的。它完美平衡了工程落地和学术创新！

前端（RTMPose-l）： MHF 默认 Demo 表现不佳，90% 是因为古董级 YOLOv3+HRNet 漏检和抖动。换成 OpenMMLab 的 RTMPose-l，2D 坐标的准度和稳定性会发生质的飞跃。甲方看了绝对满意。

后端（MotionAGFormer / MMCPose）： 这两个都是目前非常靠谱的 SOTA 级别模型。特别是 MotionAGFormer，它结合了图卷积（GCN）和 Transformer，时空建模能力极强。

发论文的突破口（物理约束）： 现成的模型组合发不了好论文，但**“+ 物理约束”就是你发论文的切入点！** 作为软工学生，你可以说：“针对真实落地场景中 3D 姿态容易产生物理违规（如脚底打滑、骨骼拉伸）的问题，本文提出了一种在损失函数中引入动力学与运动学双重物理约束的微调框架……”

综合建议： 全力攻克这个方案。 工程上，它能给出极度漂亮的可视化结果（甲方开心）；学术上，加物理约束（Physics-informed）属于目前很好中论文的“微创新”（导师开心）。

### 1.3. 方案 3：P-STMO（“学术陷阱”方案）

对甲方的可行性：低。 P-STMO 是 2022 年 ECCV 的论文。它是一个 3D 提升模型，也就是说，如果你的 2D 前端还是那个烂 HRNet，P-STMO 算出来的 3D 依然会乱飘。它解决不了甲方最直观的“Demo 效果差”的问题。

对发论文的可行性：低。 P-STMO 核心是“掩码自编码器预训练（MAE）”。如果你直接拿来用，那只是复现别人的论文。如果你要改它的核心，MAE 预训练极其吃算力和时间，不适合你这种需要“即时发论文”的状态。

综合建议： 别碰。它费时费力，且两头不讨好。
